# Pixel-Campus

Unity에서 한림 SmartLEAD의 **과목별 알림·쪽지와 과제 일정**, 한림대학교 홈페이지의 **공개 공지**를 확인하는 픽셀 캠퍼스입니다. 과목 큐브의 색으로 과제 마감이 얼마나 가까운지 표시하고, 분산된 학교 공지를 한 목록에서 검색할 수 있습니다.

## 최근 추가·개선 사항

- **모바일 세로 화면:** 에디터 Game 뷰에 540×960(9:16) 미리보기를 자동 적용합니다. Android로 빌드 대상을 바꿔도 같은 비율을 선택하며, 안전 영역을 반영합니다.
- **로그인 세션 유지:** 최초 실행과 재접속 시 기존 학교 세션부터 확인합니다. 로그인된 상태에서 로그인 페이지를 다시 열어 로그아웃을 요구하던 흐름을 수정했습니다.
- **로그인 정보 기억·자동 로그인:** 학교 로그인 화면에서 **이 기기에 ID 저장**과 **자동 로그인**을 선택할 수 있습니다. 로그인 성공이 확인된 ID만 저장하며, 자동 로그인을 켜면 비밀번호도 Windows 자격 증명 관리자 또는 Android Keystore의 AES-GCM 암호화로 보호해 저장합니다. 기존 학교 세션을 먼저 확인하고 세션이 없으면 저장된 계정으로 앱 실행당 한 번 자동 로그인을 시도합니다. 실패하면 직접 수정할 수 있으며 추가 인증은 학교 화면에서 진행합니다. 옵션을 끄거나 알림 상세의 **저장된 ID·비밀번호 삭제 / 자동 로그인 해제**로 제거할 수 있습니다. 학교에서 명시적으로 로그아웃하면 자동 로그인을 해제하고 저장된 비밀번호를 지웁니다. 로그인 직후·앱 일시정지·종료 시 WebView에 쿠키 저장을 요청합니다.
  - SmartLEAD의 `/login.php`, `/login/index.php`와 학교 통합인증의 `https://sso.hallym.ac.kr/Account/LogIn`을 지원합니다. 앱의 자동 로그인 옵션은 학교의 **ID 기억하기**와 별개이며 **로그인 버튼 위**에 표시합니다. 통합인증 화면에서는 로그인 입력만 수신하고, 성공 여부는 SmartLEAD로 돌아온 뒤 확인합니다.
- **앱 내부 과제 상세:** 과제 목록·일정의 과제를 누르면 픽셀 캠퍼스 전용 상세 화면에서 학교의 과제 본문 서식, 이미지, 안내 첨부파일과 제출 상황 표 전체를 표시합니다. 로그인된 수집 WebView에서 해당 영역을 가져와 앱 문서로 렌더링하므로 과제 원문 페이지로 이동하지 않습니다. 학교 이미지도 인증된 세션에서 가져와 본문에 포함합니다. **새로고침**으로 갱신하고 **뒤로**로 목록·캠퍼스에 돌아갑니다. **제출 완료 과제도 보기**도 지원합니다. 현재 상세는 조회용이며 학교의 파일 제출·수정·댓글 작성 폼은 포함하지 않습니다. 첨부파일을 명시적으로 선택한 경우에만 앱 내부 파일 뷰어로 엽니다. 상세 조회 실패·시간 초과는 앱 안에 안내하며 원문으로 자동 이동하지 않습니다.
- **과목 선택과 상세 보기:** PC에서는 큐브·과목명을 좌클릭하고, 모바일에서는 터치해 해당 과목의 과제·알림·쪽지 상세 목록을 엽니다.
- **알림 패널 닫기:** 패널 상단·목록 맨 위에서 아래로 스와이프하면 캠퍼스로 돌아옵니다. PC에서는 마우스 좌클릭 드래그로도 같은 동작을 할 수 있습니다. 목록 중간에서 시작한 드래그는 스크롤로 처리합니다.
- **과제 수집:** 수강 과목과 과제명, 제출 여부, 마감일을 가져옵니다. 제출 완료 과제는 기본 목록에서 제외하며, 확인 가능한 개인 연장 기한을 반영합니다.
- **과제 우선 표시:** 미제출 과제가 있는 과목을 먼저 배치합니다. 앞으로 마감되는 과제를 가까운 순으로 표시하고, 마감이 지난 과제와 마감 정보가 없는 과제는 뒤에 표시합니다.
- **남은 과제 일정:** 큐브 아래에 과목명·과제명·마감 시각·남은 시간을 표시합니다. 일정을 선택하면 해당 항목의 상세 내용을 엽니다.
- **작은 과목 카드와 스크롤:** 과목 목록을 알림 유무와 별도로 수집합니다. 알림이 없는 과목도 표시하며, 화면을 넘는 과목과 일정은 마우스 휠이나 터치 스크롤로 확인합니다.
- **빈 목록과 조회 실패 구분:** 확인된 알림과 미제출 과제가 없으면 **알림 없음**, 조회 실패나 미확인 상태는 **과제 확인 필요 / 제출 확인 필요**로 구분합니다.
- **실제 SmartLEAD 화면 대응:** Coursemos의 과목 목록과 과제 표에 맞춰 수집 경로를 수정했습니다. 과목 API와 `#region-main`에만 의존해 과제를 가져오지 못하던 문제를 해결했습니다.
- **Android 연결 준비:** 공식 Android WebView 플러그인과 `Unity.call` 통신 경로를 추가했습니다. 뒤로가기, 앱 복귀·네트워크 복구 시 갱신, 접을 수 있는 터치 이동 패드를 지원합니다. Android 실기기 동작은 아직 검증하지 않았습니다.

## 실행

1. Unity Hub에서 **Unity 6.3 LTS (6000.3.26f1)**로 이 프로젝트를 엽니다.
2. Windows에 WebView2 Runtime이 설치되어 있어야 합니다.
3. 프로젝트를 열면 Game 뷰에 540×960(9:16) 세로 미리보기가 자동 적용됩니다. Android로 빌드 대상을 바꿔도 같은 비율을 적용합니다. `Tools > Pixel Campus > Open Portrait Demo`로 데모 씬을 열고 Play를 누릅니다. 비율을 다시 적용하려면 `Tools > Pixel Campus > Use Portrait Screen`을 선택합니다.
4. 유효한 학교 세션이 남아 있으면 확인 후 바로 캠퍼스로 이동합니다. 세션이 없거나 만료됐으면 표시되는 SmartLEAD 페이지에서 직접 로그인합니다.
5. 캠퍼스의 과목 큐브와 **남은 과제 일정**을 확인합니다. 큐브·과목명·일정을 좌클릭하거나 터치하면 상세 목록이 열립니다.
6. 상세 목록의 항목을 선택해 본문을 펼칩니다. **전체 알림 보기**로 전체 목록을 확인할 수 있습니다. 원문 링크가 제공된 항목은 **학교에서 원문 보기**로 이동할 수 있으며, 패널을 아래로 스와이프해 캠퍼스에 돌아옵니다.
7. **일정 다시 확인**으로 즉시 갱신하거나 **학교 일정 보기**로 학교 캘린더를 엽니다. **계정** 버튼으로 학교 계정 화면을 확인하고, 학교 화면 상단의 **캠퍼스** 버튼으로 돌아옵니다.
8. 캠퍼스 오른쪽 위 **로그아웃**을 누르면 저장된 ID·비밀번호와 자동 로그인 설정, 앱 WebView의 로그인 쿠키를 지우고 학교 로그인 화면으로 돌아갑니다. 다음 로그인 화면의 비밀번호는 비우며 앱을 재실행해도 자동 로그인 해제를 유지합니다. 학교의 원래 로그인·통합인증 절차로 로그인하고, 보호된 학교 페이지에서 인증 성공을 확인한 뒤 캠퍼스로 이동합니다. 학교 로그아웃 요청이 실패해도 기기의 로그인 정보는 제거합니다.

## 표시 정보와 갱신

화면 상단 **학교 공지**에서 메인 홈페이지·SW중심대학사업단·학과·부속기관의 공개 공지를 함께 봅니다. 2026-10-20 공식 사이트 링크 650개를 탐색하여 79개 사이트의 RSS 게시판 241개를 기본 목록에 등록했습니다. 모든 소속 홈페이지의 수집을 보장하지 않으며, 로그인 전용·외부 서비스·RSS 미제공 게시판은 제외됩니다. `node NotificationServer/discover-university-boards.mjs`로 공식 링크에서 목록을 다시 생성할 수 있습니다. 결과 JSON에는 탐색일·확인 페이지 수·RSS 미발견 사이트·연결 실패가 포함됩니다.

SmartLEAD 로그인과 별도로 RSS를 직접 조회하므로 로컬 Node 서버나 학교 로그인이 필요하지 않습니다. 앱 실행 중 15분마다 갱신하고 **다시 확인**으로 수동 갱신합니다. 동시에 최대 4개 게시판을 조회하고 게시판별 최근 최대 50건을 가져옵니다. 최근 90일 공지는 공개 원문도 확인해 RSS에서 잘린 신청 일정을 보완합니다. 게시판을 많이 등록한 첫 실행은 원문 확인에 시간이 걸리며 수집 중에도 받은 공지를 볼 수 있습니다. 기본 **최근 90일**에서 30일·수집 전체로 변경할 수 있습니다. **출처 선택**에서 기관 이름으로 검색하고, 제목/내용 검색·안 읽음 필터를 사용할 수 있습니다.

**신청·제출 일정**은 신청·접수·제출·모집 기한과 연결된 날짜만 사용하고, 행사일·강의 운영일·게시일은 마감으로 사용하지 않습니다. 신청 시작 전에는 시작까지, 시작 후에는 마감까지 남은 시간을 표시합니다. 선착순 공지는 시작일을 우선 보여주고 종료일이 없으면 **신청 가능 · 선착순 마감**으로 표시합니다. 실제 잔여 인원·신청 완료 여부는 외부 사이트에서 자동 확인하지 않습니다. **신청/제출 완료로 표시**하면 이 기기에서 숨기고 **완료 포함**으로 복원할 수 있습니다. 단순히 읽는 것은 완료 처리가 아닙니다. 마감색은 과제와 같은 7일·3일·24시간 기준입니다. 종료 날짜만 있고 시각이 없으면 해당 날짜 23:59:59를 표시 기준으로 사용하고 **시각 미기재**를 붙입니다. 시작 시각이 없으면 날짜만 표시합니다. 복수 기한·해석 불가·이미지/첨부파일에만 있는 날짜는 원문 확인으로 안내합니다. 펼친 공지에서 추출 근거와 원문 링크를 볼 수 있습니다.

**게시판 추가**에 학과·부서 이름과 공개 게시판 HTTPS 주소(또는 RSS 주소)를 입력하면 RSS를 검증해 이 기기에 등록합니다. 기본 주소는 `Assets/Notifications/Resources/UniversityNoticeBoards.json`에 있습니다. 저장된 사용자 게시판 목록과 새 기본 목록을 합치므로 업데이트로 추가된 출처도 표시됩니다. 수집 결과와 원문 확인 시각은 `Application.persistentDataPath/university-notices-v1.json`에 저장하고, 일부 게시판이 실패하면 해당 게시판의 마지막 정상 데이터를 유지하면서 실패 상태와 마지막 성공 시각을 표시합니다. 읽음·수동 완료 상태는 PlayerPrefs에 저장합니다. 앱을 종료한 동안의 백그라운드 수집·푸시 알림은 제공하지 않습니다.

과목 큐브의 기본색은 흰색입니다. 미제출 과제의 남은 시간이 7일 초과면 회색(여유), 3일 초과~7일 이하면 노랑(주의), 24시간 초과~3일 이하면 주황(경고), 0초 초과~24시간 이하면 빨강(긴급), 마감 시각부터는 어두운 회색(만료)으로 표시합니다. 제출 시작 시각은 필요하지 않습니다. 과목 큐브와 과목 알림창은 진행 중인 과제 중 가장 긴급한 단계를 사용하며, 모든 남은 과제가 만료되면 만료색을 사용합니다. 각 일정·알림 항목은 연결된 과제의 색을 사용합니다. 제출 완료 과제는 제외하고 개인 연장 기한을 반영합니다. 마감 정보가 없거나 남은 과제가 없으면 흰색입니다. 색상은 현재 시각에 맞춰 갱신됩니다.

과목 카드와 알림 상세에 강의실을 표시합니다. 2026-2학기 강의계획서에서 확인한 네 과목의 강의실은 `CourseClassrooms.json`에 등록했습니다. 커리어잉글리쉬처럼 추가 인증 때문에 확인하지 못한 과목은 미확인으로 표시합니다. 과목 상세의 **강의실 입력 / 수정**에서 수강신청 앱·시간표로 확인한 강의실을 입력하고 **이 기기에 저장**을 누르면 다음 실행에도 표시됩니다. 요일에 따라 교실이 다르면 함께 적을 수 있습니다. 직접 입력한 값이 기본 등록값보다 우선하며, **입력값 초기화**로 기본 등록값으로 돌아갑니다. 저장값은 한국 시간 기준 학기(3~8월 1학기, 9~다음 해 2월 2학기)와 과목·분반별로 구분합니다. 수강신청 앱 자동 연동은 구현하지 않았습니다.

| 화면 | 표시 내용 |
| --- | --- |
| 과목 카드 | 과목명·과목 코드, 미제출 과제 수, 가까운 과제명과 남은 시간, 알림 건수 |
| 남은 과제 일정 | 과목명·과제명, 한국 시간 기준 마감일, 남은 시간 또는 마감 경과 시간 |
| 상세 목록 | 미제출 과제 우선, 읽지 않았거나 읽음 여부가 미확인인 알림·쪽지, 본문과 제공된 원문 링크 |
| 확인된 빈 목록 | **알림 없음 / 남은 과제 없음** |
| 조회 실패·불확실한 상태 | **과제 확인 필요 / 제출 확인 필요 / 전체 과목 확인 필요** |

학교 데이터는 앱 실행 중 **2분 간격**으로 갱신하며 수동으로도 다시 확인할 수 있습니다. 남은 시간은 기기의 현재 시각으로 계속 계산합니다. 일반 알림은 제공된 마감 정보나 연결된 과제의 마감일을 확인할 수 있을 때만 남은 시간을 표시합니다.

## SmartLEAD 수집 방식

홈의 **동영상 출석 일정**과 과목 상세의 **동영상 출석 일정**에서 강의별 출석 인정 시작·종료, 남은 시간, 학교에서 확인한 출결을 표시합니다. 지각 인정 종료가 제공되면 출석 기간과 구분해 표시합니다. 출석 확인된 영상은 기본 목록에서 제외하며 **출석 확인된 동영상도 보기**로 다시 볼 수 있습니다. 출석 인정 마감도 과목 큐브의 색·정렬에 반영합니다. 진도율 100%·활동 완료 체크만으로 출석 완료를 판단하지 않습니다.

동영상 수집은 수강 중인 과목의 강의실·동영상 목록과 강의실에서 연결한 온라인출석부/학습진도현황의 읽기 전용 페이지를 사용합니다. Coursemos의 `vod`/`ubvod` 모듈 링크, 제목 옆의 출석/진도 기간, 표의 출석·지각 기간과 주차별 rowspan/colspan 구조를 처리합니다. 날짜는 한국 시간으로 해석합니다. 재생 가능 기간을 출석 인정 기간으로 바꿔 표시하지 않습니다. 날짜·출석 상태가 없거나 페이지 구조/조회 범위가 불확실하면 **확인 필요**로 표시하고, 조회 실패 때 보존한 이전 데이터에는 **이전 조회 정보**를 붙입니다. 과목당 추가 주차 페이지는 최대 12개까지 읽고 더 있으면 일부 조회로 표시합니다. 다른 모듈·동적 로딩 전용 출석부·학교별 화면은 추가 대응이 필요할 수 있습니다.

**강의 보기**는 로그인된 학교 플레이어를 앱 안에 엽니다. 출석 수집 과정에서는 영상 플레이어를 열지 않고, 학습시간·출석 기록을 보내거나 완료 처리하지 않습니다. 강의를 시청하는 동안 앱 복귀·정기 갱신으로 플레이어를 새로고침하지 않으며, **캠퍼스/뒤로**로 나가면 출석 일정을 다시 조회합니다. 실제 시청 기록·출석 인정은 학교 플레이어와 온라인출석부의 결과를 확인해야 합니다. 예시 DOM 수집·시간 경계 테스트와 Windows/Android C# 컴파일로 검증하며, 실제 SmartLEAD 강의별 수집 및 시청 기록은 추가 확인이 필요합니다.

동영상 검증: `node NotificationServer/check-video-attendance.cjs`(Playwright 필요), `powershell -NoProfile -File NotificationServer/test-lecture-attendance.ps1`.

과제 상세의 **파일 첨부·제출**은 로그인 세션이 있는 학교 과제 화면을 앱 안에 엽니다. 학교의 파일 선택도구로 첨부하고 **저장**하며, 제출 여부가 **제출물 초안**이면 **과제 제출 완료하기**까지 진행합니다. 파일 선택기를 다녀오거나 앱에 복귀할 때 제출 화면을 자동 새로고침하지 않습니다. 상단 **뒤로**로 상세에 돌아오면 학교의 제출 상태를 다시 조회합니다. 과제별 업로드 용량·개수·확장자·마감·조별 제출 조건은 학교 화면에서 처리합니다. 실제 학교 파일 업로드와 Android 기기 동작은 추가 확인이 필요합니다.

학교 제출 화면 상단의 **제출 파일 형식**에서 **한글 문서 (.hwp)** 또는 **한글 표준 문서 (.hwpx)**를 선택하면, 파일 선택도구로 추가한 DOCX·DOC·RTF·HWP·HWPX 문서를 Windows PC에 설치된 한컴오피스 한글 엔진으로 실제 변환합니다. 원본은 그대로 두고 변환된 파일명과 크기를 확인한 뒤 **변환 파일 사용**을 누르면 학교 파일 선택도구에 전달합니다. 학교 화면의 업로드·저장·최종 제출 절차는 직접 진행합니다. 변환 실패·취소 시 원본을 대신 업로드하지 않습니다. 변환 과정에서 한컴의 파일 접근 승인창이 나타나면 직접 승인해야 하며, 보안 설정을 변경하거나 승인창을 자동 처리하지 않습니다.

한글 변환은 **Windows + 편집 가능한 한컴오피스 한글**이 필요합니다. Android·한글 미설치·뷰어만 설치된 기기는 원본 첨부를 사용합니다. 입력 16MB·결과 32MB까지 처리하며, 학교의 별도 용량 제한도 적용됩니다. PDF·스캔 이미지의 OCR이나 편집 가능한 한글 문서 재구성은 지원하지 않습니다. 표·글꼴·페이지 배치는 변환 중 바뀔 수 있습니다. HWP는 OLE/HWP 헤더, HWPX는 ZIP 내부 문서 구조와 MIME을 검사하므로 확장자만 바꾼 파일을 변환 완료로 취급하지 않습니다. 변환할 문서는 드래그 앤 드롭 대신 **파일 선택** 버튼으로 추가합니다.

검증은 `powershell -NoProfile -File NotificationServer/test-submission-conversion.ps1`, 한글 설치 PC에서 실제 변환까지 확인하려면 같은 명령에 `-Integration`을 붙입니다. `NotificationServer/check-submission-conversion.cjs`는 Playwright 예시 화면으로 파일 전달·변환 실패·취소·잘못된 응답 거부를 검사합니다. 실제 학교 서버에는 테스트 파일을 전송하지 않습니다.

로그인된 WebView 세션에서 Moodle 과목·과제·제출 상태 API를 먼저 시도하고, 제공되지 않으면 학교 대시보드와 과제 페이지를 읽습니다. 현재 SmartLEAD의 Coursemos 화면에서는 다음 구조를 지원합니다.

- `.course-info-container`와 `[role="main"]`의 과목·과제 목록
- 과제 표의 **종료 일시 / 제출** 열과 상세 화면의 **제출 여부**
- 한국 시간 기준 `YYYY-MM-DD HH:mm` 및 한국어 날짜 표기

학교 캘린더도 별도로 조회하므로 과목·과제 API가 차단돼도 조회 가능한 마감 일정부터 표시합니다. 캘린더 일정의 제출 완료 여부를 확인하지 못하면 **제출 확인 필요**를 표시합니다. 제출 완료 과제는 연결된 캘린더 일정과 중복 표시하지 않으며, 현재 수강 목록에 없는 지난 학기의 마감된 캘린더 과제는 제외합니다.

과목 목록의 전체 범위를 보장할 수 없는 대체 조회는 **전체 과목 확인 필요**로 표시합니다. 조회 실패를 과제 0건으로 처리하지 않으며, 45초 이상 지연되면 계속 대기하는 대신 안내를 표시합니다. 알림 기록은 학교에서 다시 확인할 수 있도록 **학교 알림 기록 보기**를 제공합니다.

## 지원 환경과 개발 범위

- **현재 검증 환경:** Windows x64, Unity 6.3 LTS 에디터, WebView2 Runtime.
- **Android 구현:** 공식 WebView AAR, 세로 화면·안전 영역, 알림·과제 수신, 터치 스크롤·스와이프 닫기, 뒤로가기, 앱 복귀 시 갱신과 터치 이동 패드를 추가했습니다. ARMv7·ARM64와 IL2CPP를 설정했습니다. Android 조건의 소스 컴파일과 통신 테스트는 통과했으며 실기기 검증은 남아 있습니다.
- **위젯·백그라운드 알림:** 홈 화면 위젯, 푸시 알림과 앱 종료 상태의 자동 조회는 아직 구현하지 않았습니다.
- **로그인 정보:** 학교 페이지에서 로그인합니다. 자동 로그인을 선택한 경우 비밀번호는 기기의 보호 저장소에 저장하며 프로젝트 파일·평문 PlayerPrefs에는 기록하지 않습니다. Windows 보호 저장소와 Android 구현을 제공하며 Android 실기기 검증은 남아 있습니다.

알림 연결의 세부 설정은 [WEBVIEW-SETUP.ko.md](WEBVIEW-SETUP.ko.md)를 참고하세요.

Android에 추가한 파일, 권한, 조작 방법과 추후 기기에서 확인할 항목은 [Android 사용 안내](docs/ANDROID.ko.md)에 정리했습니다.

## 검증

2026-10-19 기준으로 Windows 에디터의 실제 로그인된 SmartLEAD 세션에서 수강 과목·과제·제출 여부·마감일 수집과 Game 뷰의 일정 표시를 확인했습니다. Android·Windows 통신 경로를 포함한 관련 수집 테스트 **23개**를 통과했습니다. Android 실기기 로그인·키보드·뒤로가기는 별도 검증이 필요합니다.

```powershell
cd NotificationServer
node --test capture.test.mjs coursework.test.mjs
```

로그인 자동 입력·자동 제출과 과제 상세 조회 검증에는 `node --test NotificationServer/login.test.mjs NotificationServer/coursework.test.mjs NotificationServer/capture.test.mjs`를 사용합니다. Windows 보호 저장소의 저장·복원·변경·삭제와 Android 보호 저장소 소스 컴파일은 `./NotificationServer/test-smartlead-credentials.ps1`로 확인합니다. 보호 저장소 테스트는 매번 고유한 가짜 계정을 만들고 종료 시 삭제합니다.

과제 HTML 상세의 실제 DOM 검사는 `node NotificationServer/check-assignment-document.cjs` 실행 후 로컬 미리보기 `http://127.0.0.1:8792`를 열어 확인합니다. 실제 계정 대신 예시 데이터를 사용하며 문단 서식·보호 이미지의 인라인 포함·안내 및 제출 파일·제출 표·긴 문서 분할·로그인 만료·불필요한 학교 메뉴 및 실행 코드 제거 등 13개 검사를 표시합니다. Unity WebView와 실제 학교 계정의 최종 동작 확인은 별도입니다.

홈페이지 공지 파싱·학교 도메인 링크·날짜/중복 처리 검증은 프로젝트 루트에서 `./NotificationServer/test-university-notices.ps1`로 실행합니다. Unity가 생성한 `Assembly-CSharp.csproj`와 .NET 10 SDK를 사용하며 생성 파일은 `Temp/UniversityNoticeChecks`에만 만듭니다.

테스트에는 로그인 만료, 읽은 알림 기록, 과목 목록 대체 조회, Coursemos 과제 표, 마감일과 연장 기한, 캘린더 대체 조회, 응답 시간 초과 처리가 포함됩니다.

## 파일 구성

- `Assets/`: 스크립트, 씬, 리소스, 플러그인과 `.meta` 파일
- `Packages/`: Unity 패키지 목록과 잠금 파일
- `ProjectSettings/`: Unity 프로젝트 설정
- `NotificationServer/`: 선택적으로 사용하는 로컬 서버와 테스트
- `BrowserBridge/`: 브라우저 확장 기반의 보조 연결 코드
- `docs/TROUBLESHOOTING.ko.md`: 사용한 방법, 오류 원인·해결·검증 내역과 추가 기록 양식
- `docs/ANDROID.ko.md`: Android용 파일·권한·조작 방법과 실기기 확인 항목

`Library`, `Temp`, 로그, 빌드 결과물과 개인 계정의 알림 데이터는 Git에서 제외합니다. 옆에 있는 별도 CLI 비교 프로젝트도 이 저장소에는 포함하지 않습니다. Unity에서 `Library` 등은 프로젝트를 열 때 다시 생성합니다.

## 변경 사항 저장하기

Unity에서 씬과 에셋을 저장한 뒤 프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
git status
git add Assets Packages ProjectSettings NotificationServer BrowserBridge docs README.md WEBVIEW-SETUP.ko.md .gitignore .gitattributes
git commit -m "Describe the change"
git push
```

작업을 시작하기 전에는 `git pull --ff-only`로 최신 변경을 받습니다. Unity의 `.meta` 파일은 에셋과 함께 커밋해야 씬 참조가 유지됩니다. 변경 목적마다 커밋을 나누면 이전 상태를 찾기 쉽습니다.

## 새 컴퓨터에서 받기

```powershell
git clone https://github.com/han183536-ux/Pixel-Campus.git
```

Unity Hub에서 복제한 폴더를 추가하고 지정한 Unity 버전으로 엽니다. 개인 계정의 로그인 상태는 새 컴퓨터에서 다시 확인해야 합니다.

## 로컬 서버 테스트

Node.js 20 이상에서 실행합니다. 현재 WebView 알림 조회 모드에는 이 서버가 필수는 아닙니다.

```powershell
cd NotificationServer
node --test
```

서버 연결 방식은 [NotificationServer/README.ko.md](NotificationServer/README.ko.md)를 참고하세요. 파일 기반 연결에는 `smartlead.notifications.example.json`을 `smartlead.notifications.json`으로 복사한 뒤 사용합니다. 실제 알림 파일은 Git에서 제외됩니다.

## 라이선스와 기획

라이선스와 기획 내용은 추후 추가합니다. 포함된 UnityWebView 플러그인의 라이선스와 출처는 `Assets/Plugins/UnityWebView/`에서 확인할 수 있습니다.
