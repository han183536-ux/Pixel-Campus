# Pixel-Campus

한림대학교 캠퍼스 지도에서 SmartLEAD의 **수강 과목, 주차별 강의 자료, 알림·쪽지, 과제**를 확인하는 Unity 앱입니다. 학교 홈페이지의 **공개 공지와 신청 일정**도 한 화면에서 검색할 수 있습니다.

## 지금까지 반영한 변경

### 화면과 캠퍼스 지도

- 하단 메뉴는 **과목 · 과제 · 지도 · 공지 · 계정** 순서입니다. 각 아이콘 아래에 메뉴 이름을 배치했습니다. Pretendard를 적용하고 앱의 주요 카드·버튼·패널은 공통 모서리 반경 12px를 사용합니다.
- 지도 화면에서 상단 로고와 제목을 제거했습니다. 과목·과제·공지·계정은 어둡고 흐려진 지도 위에 반투명 패널로 열립니다. 하단 **지도**를 누르거나 패널 상단을 아래로 끌어 돌아갑니다. 자료 상세와 과제 상세에는 왼쪽 뒤로가기 화살표가 있습니다.
- 실제 건물 윤곽과 도로를 바탕으로 북쪽이 위인 평면 캠퍼스 지도를 그렸습니다. 도로·건물·녹지는 저채도 색으로 표시하며, **전체** 보기에서 캠퍼스 전체를 세로 화면에 맞춥니다. 드래그로 이동하고 휠·두 손가락 또는 **+ / −**로 최대 8배까지 확대합니다. 마지막 위치와 배율을 저장하며, **전체**나 선택된 **지도** 탭을 다시 누르면 전체 보기로 돌아옵니다. 지도 데이터 © OpenStreetMap contributors. [캠퍼스 지도 데이터](https://www.openstreetmap.org/way/300174107) · [데이터 라이선스](https://www.openstreetmap.org/copyright)
- 공학관·자연과학관·기초교육관의 실제 건물 위치 근처에 강의 아이콘을 배치합니다. 같은 건물의 강의는 연결선 없이 모아 표시하며, 각 아이콘을 누르면 해당 과목의 과제와 알림이 열립니다. 알림이 여러 건이면 아이콘을 최대 세 겹으로 표시하고 건수 배지를 붙입니다.
- Game 뷰에 **540×960(9:16)** 세로 미리보기를 자동 적용합니다. Android 빌드 대상에도 같은 미리보기를 적용하며, 앱 화면은 기기의 안전 영역을 반영합니다.

### 과목, 강의 자료와 알림

- **과목**은 알림이 없는 과목까지 포함해 현재 수강 목록을 과목명순으로 보여줍니다. 한 줄에 카드 한 개를 배치하고 과목명·과목 코드·확인된 강의실과 분반 번호를 표시합니다.
- **강의 정보**에서 강의 개요와 학교에 등록된 주차를 펼쳐 볼 수 있습니다. 자료 카드에는 파일 형식 배지, 제목과 학교가 제공한 설명 일부가 표시됩니다. 자료를 누르면 앱 안에서 전체 설명과 확인된 파일명, 동영상의 출석 정보를 볼 수 있습니다. 과제는 기존 과제 상세로 바로 열립니다. 자료 상세에서 뒤로 가면 펼쳐 둔 주차와 목록 위치를 복원합니다.
- **과제와 알림**에서 과목별 과제·알림·쪽지·동영상 출석을 확인합니다. 하단 **과제**에는 남은 과제를 마감이 가까운 순으로 표시하고, 완료된 과제는 과목 상세의 **제출 완료 과제 표시**에서 확인할 수 있습니다.
- 과제 카드는 왼쪽 마감 표시색을 카드 배경의 그라데이션에 사용합니다. 마우스를 올리면 배경은 표시색으로, 왼쪽 표시는 흰색으로 바뀝니다. 제목과 설명의 글자색은 유지합니다.
- **공지**는 저장된 목록을 먼저 표시하고 갱신은 백그라운드에서 진행합니다. 처음에는 24개를 표시하며 **더 보기**로 이어서 볼 수 있습니다. 과목·과제·공지에는 조회 성공 건수 같은 진단 문구를 줄이고, 빈 목록·조회 중·조회 실패 안내를 필요한 경우에 표시합니다.

### 과제 상세와 제출

- 상단에 과목명과 왼쪽 뒤로가기 화살표를 표시합니다. 로그인된 SmartLEAD 세션에서 과제 본문, 표, 이미지, 첨부파일과 제출 현황을 읽어 앱의 상세 화면에 표시합니다. 보호된 이미지를 불러와 미리 보기를 만들고, 동영상은 본문에서 재생할 수 있습니다. 미리보기 재생이 실패하면 안내와 파일 열기 링크가 표시됩니다.
- **파일 첨부**와 **업로드·저장** 영역은 상세 화면 아래쪽에 고정됩니다. 파일 선택기를 바로 열고 파일명·용량을 확인한 뒤 업로드할 수 있습니다. 학교 양식에서 온라인 답안, 동의 또는 최종 제출을 처리해야 할 때는 **추가 제출 옵션**을 사용합니다. 지원 범위와 검증 결과는 아래 [과제 파일 업로드](#과제-파일-업로드)에 정리했습니다.

### 로그인 및 기기 지원

- 최초 실행과 재접속 시 기존 SmartLEAD 세션부터 확인합니다. 로그인 화면의 **이 기기에 ID 저장**과 **자동 로그인**은 로그인 성공이 확인된 계정에 적용합니다. 자동 로그인 비밀번호는 Windows 자격 증명 관리자 또는 Android Keystore로 보호합니다. **계정 → 이 기기의 저장된 로그인 삭제** 또는 **로그아웃**으로 저장 정보를 지울 수 있습니다.
- SmartLEAD의 `/login.php`, `/login/index.php`와 학교 통합인증을 지원합니다. 자동 로그인 옵션은 로그인 버튼 위에 표시되고, 통합인증 성공은 SmartLEAD에 돌아온 뒤 확인합니다. WebView의 쿠키는 로그인 직후, 앱 일시정지 및 종료 시 저장합니다.
- Android용 공식 WebView와 `Unity.call` 통신, 파일 선택기, 터치 스크롤·패널 닫기, 뒤로가기, 복귀 및 네트워크 복구 시 갱신을 추가했습니다. 실기기 검증은 남아 있습니다.

## 실행

**Windows 11 x64에서 앱으로 실행**하려면 [Windows 배포판](https://github.com/han183536-ux/Pixel-Campus/releases/latest)에서 `PixelCampus-Windows-x64.zip`을 내려받으세요. ZIP 전체를 로컬 폴더에 풀고 `PixelCampus.exe`를 엽니다. Unity, Visual C++ 재배포 패키지, WebView2를 따로 설치할 필요가 없습니다. 학교 로그인에는 인터넷 연결이 필요합니다.

### Unity 에디터로 개발

1. Unity Hub에서 **Unity 6.3 LTS (6000.3.26f1)**로 이 프로젝트를 엽니다.
2. Windows x64 에디터는 PC에 설치된 [WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)과 [Visual C++ x64 런타임](https://aka.ms/vc14/vc_redist.x64.exe)을 사용합니다.
3. 프로젝트를 열면 Game 뷰에 540×960(9:16) 세로 미리보기가 자동 적용됩니다. Android로 빌드 대상을 바꿔도 같은 비율을 적용합니다. `Tools > Pixel Campus > Open Portrait Demo`로 데모 씬을 열고 Play를 누릅니다. 비율을 다시 적용하려면 `Tools > Pixel Campus > Use Portrait Screen`을 선택합니다.
4. 유효한 학교 세션이 남아 있으면 확인 후 바로 캠퍼스로 이동합니다. 세션이 없거나 만료됐으면 표시되는 SmartLEAD 페이지에서 직접 로그인합니다.
5. 지도 위의 알림 아이콘을 눌러 과목 알림을 열거나 하단 **과목**에서 강의 정보를 확인합니다. 하단 **과제**에서 마감 일정과 제출 화면을 열 수 있습니다. **과제 다시 확인**으로 갱신하고 **학교 일정 보기**로 SmartLEAD 캘린더를 엽니다.
6. **계정 → 로그아웃**을 누르면 기기에 저장된 로그인 정보와 자동 로그인 설정, 앱 WebView 쿠키가 지워지고 학교 로그인 화면으로 돌아갑니다. 다음 로그인은 학교 로그인 또는 통합인증으로 진행합니다.

**새 PC에서 로그인 창이 열리지 않을 때** — Windows 배포판은 동봉한 WebView2를 먼저 사용합니다. 필요한 브라우저 파일이 없으면 Windows에 설치된 WebView2를 사용하고, 동봉한 브라우저가 초기화에 실패하면 앱을 한 번 다시 열어 시스템 WebView2로 시도합니다. 그래도 실패하면 **오류 정보 복사**로 화면의 진단 내용을 전달할 수 있습니다. 에디터 콘솔에 `DllNotFoundException`이 뜨면 `Assets/Plugins/UnityWebView/Windows/x64/WebView.dll`과 Visual C++ x64 런타임을 확인합니다. 이미 웹뷰가 열렸지만 학교 세션 확인에 15초 동안 응답이 없으면 앱이 로그인 페이지를 한 번 엽니다. 이 페이지에서도 응답이 없으면 네트워크 연결을 확인한 뒤 **재접속**을 누릅니다.

Unity CLI가 설치된 Windows에서는 프로젝트 루트에서 에디터를 열고 컴파일을 확인할 수 있습니다.

```powershell
unity open . --until-ready
unity recompile . --timeout 120 --non-interactive
```

### Windows 배포 ZIP 만들기

Windows x64 릴리스 플레이어를 빈 폴더에 빌드한 후 저장소 루트에서 다음 명령을 실행합니다. 처음 패키징할 때 스크립트가 Microsoft에서 x64 배포 파일을 받아 SHA-256을 검증합니다. 실제 배포에는 생성한 ZIP을 사용합니다.

```powershell
unity build . --target StandaloneWindows64 --output ./Builds/Windows/PixelCampus.exe
.\tools\Build-WindowsPortable.ps1 -PlayerExe .\Builds\Windows\PixelCampus.exe -OutputZip .\Builds\PixelCampus-Windows-x64.zip
```

WebView2 고정 버전은 앱과 함께 배포하므로 보안 업데이트 때는 패키징 스크립트의 Microsoft 배포 버전·주소·해시를 갱신해 새 ZIP을 배포합니다. 무설치 배포판은 사용자별 `%LOCALAPPDATA%\PixelCampus` 안에 동봉한 브라우저의 프로필(`WebView2`)과 Windows 브라우저의 프로필(`WebView2-System`)을 따로 저장합니다. 브라우저가 전환되면 학교에서 로그인을 한 번 더 요청할 수 있습니다.

## 표시 정보와 갱신

하단의 **공지**에서 메인 홈페이지·SW중심대학사업단·학과·부속기관의 공개 공지를 함께 봅니다. 2026-10-20 공식 사이트 링크 650개를 탐색하여 79개 사이트의 RSS 게시판 241개를 기본 목록에 등록했습니다. 모든 소속 홈페이지의 수집을 보장하지 않으며, 로그인 전용·외부 서비스·RSS 미제공 게시판은 제외됩니다. `node NotificationServer/discover-university-boards.mjs`로 공식 링크에서 목록을 다시 생성할 수 있습니다. 결과 JSON에는 탐색일·확인 페이지 수·RSS 미발견 사이트·연결 실패가 포함됩니다.

학교 공지는 SmartLEAD 로그인과 별도로 RSS를 조회합니다. 저장된 공지를 먼저 표시하고 앱 실행 중 오래된 RSS를 갱신합니다. **다시 확인**을 누르면 수동으로 갱신합니다. 공지를 펼치면 공개 원문으로 요약을 보완하고, 최근 공지의 신청 일정도 소량씩 백그라운드에서 확인합니다. 기본 **최근 90일**에서 30일이나 전체 기간으로 변경할 수 있으며, 출처·제목·내용·읽음 상태로 찾을 수 있습니다.

**신청·제출 일정**은 신청·접수·제출·모집 기한과 연결된 날짜만 사용하고, 행사일·강의 운영일·게시일은 마감으로 사용하지 않습니다. 신청 시작 전에는 시작까지, 시작 후에는 마감까지 남은 시간을 표시합니다. 선착순 공지는 시작일을 우선 보여주고 종료일이 없으면 **신청 가능 · 선착순 마감**으로 표시합니다. 실제 잔여 인원·신청 완료 여부는 외부 사이트에서 자동 확인하지 않습니다. **신청/제출 완료로 표시**하면 이 기기에서 숨기고 **완료 포함**으로 복원할 수 있습니다. 단순히 읽는 것은 완료 처리가 아닙니다. 마감색은 과제와 같은 7일·3일·24시간 기준입니다. 종료 날짜만 있고 시각이 없으면 해당 날짜 23:59:59를 표시 기준으로 사용하고 **시각 미기재**를 붙입니다. 시작 시각이 없으면 날짜만 표시합니다. 복수 기한·해석 불가·이미지/첨부파일에만 있는 날짜는 원문 확인으로 안내합니다. 펼친 공지에서 추출 근거와 원문 링크를 볼 수 있습니다.

**게시판 추가**에 학과·부서 이름과 공개 게시판 HTTPS 주소(또는 RSS 주소)를 입력하면 RSS를 검증해 이 기기에 등록합니다. 기본 주소는 `Assets/Notifications/Resources/UniversityNoticeBoards.json`에 있습니다. 저장된 사용자 게시판 목록과 새 기본 목록을 합치므로 업데이트로 추가된 출처도 표시됩니다. 수집 결과는 `Application.persistentDataPath/university-notices-v1.json`에 저장합니다. 게시판에 연결하지 못하면 마지막으로 받은 공지를 표시하며, 표시할 데이터가 없으면 다시 확인할 수 있습니다. 읽음·수동 완료 상태는 PlayerPrefs에 저장합니다. 백그라운드 확인은 앱이 실행 중일 때 진행합니다.

과제 카드의 마감색은 7일 초과면 회색(여유), 3일 초과~7일 이하면 노랑(주의), 24시간 초과~3일 이하면 주황(경고), 0초 초과~24시간 이하면 빨강(긴급), 마감 시각부터는 어두운 회색(만료)입니다. 완료된 과제는 남은 과제 목록에서 제외하며 확인된 개인 연장 기한을 반영합니다. 마감 미확인 항목은 중립 배경으로 표시합니다. 남은 시간과 색상은 기기의 현재 시각에 맞춰 갱신됩니다.

과목 카드와 알림 상세에 강의실을 표시합니다. 2026-2학기 강의계획서에서 확인한 네 과목의 강의실은 `CourseClassrooms.json`에 등록했습니다. 커리어잉글리쉬처럼 추가 인증 때문에 확인하지 못한 과목은 미확인으로 표시합니다. 과목 상세의 **강의실 입력 / 수정**에서 수강신청 앱·시간표로 확인한 강의실을 입력하고 **이 기기에 저장**을 누르면 다음 실행에도 표시됩니다. 요일에 따라 교실이 다르면 함께 적을 수 있습니다. 직접 입력한 값이 기본 등록값보다 우선하며, **입력값 초기화**로 기본 등록값으로 돌아갑니다. 저장값은 한국 시간 기준 학기(3~8월 1학기, 9~다음 해 2월 2학기)와 과목·분반별로 구분합니다. 수강신청 앱 자동 연동은 구현하지 않았습니다.

| 화면 | 표시 내용 |
| --- | --- |
| 과목 카드 | 과목명, 과목 코드, 확인된 강의실, 과목 코드에서 읽은 분반 |
| 남은 과제 일정 | 과목명·과제명, 한국 시간 기준 마감일, 남은 시간 또는 마감 경과 시간 |
| 강의 정보 | 강의 개요, 주차 목록, 주차별 자료 미리보기와 상세 |
| 과제와 알림 | 과제와 동영상 출석, 읽지 않았거나 읽음 여부가 미확인인 알림·쪽지 |
| 확인된 빈 목록 | **현재 수강 중인 과목이 없습니다 / 남은 과제가 없습니다 / 표시할 공지가 없습니다** |
| 조회 실패·불확실한 상태 | 조회 실패 안내, 제출 여부 미확인 표시, 일부 주차를 가져오지 못한 경우 다시 확인 |

학교 데이터는 앱 실행 중 **2분 간격**으로 갱신하며 수동으로도 다시 확인할 수 있습니다. 남은 시간은 기기의 현재 시각으로 계속 계산합니다. 일반 알림은 제공된 마감 정보나 연결된 과제의 마감일을 확인할 수 있을 때만 남은 시간을 표시합니다.

## SmartLEAD 수집 방식

### 동영상 출석

**과목 상세 → 과제와 알림 → 동영상 출석**에서 강의별 출석 인정 시작·종료, 남은 시간과 학교에서 확인한 출결을 표시합니다. 지각 인정 종료 시각은 별도로 표시합니다. 출석 확인된 영상은 **출석 확인된 동영상 표시**를 켜면 볼 수 있습니다. 출석 완료 여부는 학교가 확인한 출결로 판단합니다.

동영상 수집은 수강 중인 과목의 강의실·동영상 목록과 강의실에서 연결한 온라인출석부/학습진도현황의 읽기 전용 페이지를 사용합니다. Coursemos의 `vod`/`ubvod` 모듈 링크, 제목 옆의 출석/진도 기간, 표의 출석·지각 기간과 주차별 rowspan/colspan 구조를 처리합니다. 날짜는 한국 시간으로 해석합니다. 재생 가능 기간을 출석 인정 기간으로 바꿔 표시하지 않습니다. 날짜·출석 상태가 없거나 페이지 구조/조회 범위가 불확실하면 **확인 필요**로 표시하고, 조회 실패 때 보존한 이전 데이터에는 **이전 조회 정보**를 붙입니다. 과목당 추가 주차 페이지는 최대 12개까지 읽고 더 있으면 일부 조회로 표시합니다. 다른 모듈·동적 로딩 전용 출석부·학교별 화면은 추가 대응이 필요할 수 있습니다.

**강의 보기**는 로그인된 학교 플레이어를 앱 안에 엽니다. 출석 수집 과정에서는 영상 플레이어를 열지 않고, 학습시간·출석 기록을 보내거나 완료 처리하지 않습니다. 강의를 시청하는 동안 앱 복귀·정기 갱신으로 플레이어를 새로고침하지 않으며, **캠퍼스/뒤로**로 나가면 출석 일정을 다시 조회합니다. 실제 시청 기록·출석 인정은 학교 플레이어와 온라인출석부의 결과를 확인해야 합니다. 예시 DOM 수집·시간 경계 테스트와 Windows/Android C# 컴파일로 검증하며, 실제 SmartLEAD 강의별 수집 및 시청 기록은 추가 확인이 필요합니다.

동영상 검증: `node NotificationServer/check-video-attendance.cjs`(Playwright 필요), `powershell -NoProfile -File NotificationServer/test-lecture-attendance.ps1`.

### 과제 파일 업로드

과제 상세에서 **파일 첨부**를 누르고 파일을 선택한 뒤 **업로드·저장**을 누릅니다. 파일 첨부만 필요한 과제는 앱에 연결된 SmartLEAD 세션으로 파일을 올리고 저장 결과를 과제 상세에서 확인할 수 있습니다. 온라인 답안 작성이나 동의가 필요한 과제는 **추가 제출 옵션 → 학교 양식 · 최종 제출 확인**을 사용합니다. 제출 여부가 **제출물 초안**이면 해당 화면에서 최종 제출을 완료합니다. 파일 용량·개수·확장자·마감·조별 제출 조건은 과제마다 학교 설정을 따릅니다. [한림 SmartLEAD 학습자 매뉴얼](https://ilsongls.hallym.ac.kr/bbs/online/298/199041/download.do)

학교 양식은 파일 선택기를 다녀오거나 앱에 복귀할 때 유지됩니다. 왼쪽 **뒤로**로 과제 상세에 돌아오면 제출 현황을 다시 조회합니다.

**업로드 중단 원인과 검증.** 실제 SmartLEAD 제출 양식은 파일 확장자 목록(`accepted_types`)을 빈 배열로 전달할 수 있습니다. 앱이 이 값을 잘못된 양식으로 판단해 파일 전송 전에 멈추는 문제를 수정했습니다. 빈 배열이면 학교 파일 선택기처럼 확장자 목록 필드를 생략하고, 확장자 설정 자체를 읽을 수 없으면 학교 양식으로 안내합니다. 읽기 전용으로 확인한 실제 과제 양식에서 수정 전 중단과 수정 후 요청 생성을 재현했습니다. 파일 업로드·저장 응답은 모의 처리했으며 실제 학교 서버 저장, 대용량 파일, Android 기기 동작은 추가 검증이 필요합니다. [Moodle 파일 선택기 구현](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/repository/filepicker.js)

### 학교 양식에서 한글 형식 변환

학교 제출 화면 상단의 **제출 파일 형식**에서 **한글 문서 (.hwp)** 또는 **한글 표준 문서 (.hwpx)**를 선택하면, 파일 선택도구로 추가한 DOCX·DOC·RTF·HWP·HWPX 문서를 Windows PC에 설치된 한컴오피스 한글 엔진으로 실제 변환합니다. 원본은 그대로 두고 변환된 파일명과 크기를 확인한 뒤 **변환 파일 사용**을 누르면 학교 파일 선택도구에 전달합니다. 학교 화면의 업로드·저장·최종 제출 절차는 직접 진행합니다. 변환 실패·취소 시 원본을 대신 업로드하지 않습니다. 변환 과정에서 한컴의 파일 접근 승인창이 나타나면 직접 승인해야 하며, 보안 설정을 변경하거나 승인창을 자동 처리하지 않습니다.

한글 변환은 **Windows + 편집 가능한 한컴오피스 한글**이 필요합니다. Android·한글 미설치·뷰어만 설치된 기기는 원본 첨부를 사용합니다. 입력 16MB·결과 32MB까지 처리하며, 학교의 별도 용량 제한도 적용됩니다. PDF·스캔 이미지의 OCR이나 편집 가능한 한글 문서 재구성은 지원하지 않습니다. 표·글꼴·페이지 배치는 변환 중 바뀔 수 있습니다. HWP는 OLE/HWP 헤더, HWPX는 ZIP 내부 문서 구조와 MIME을 검사하므로 확장자만 바꾼 파일을 변환 완료로 취급하지 않습니다. 변환할 문서는 드래그 앤 드롭 대신 **파일 선택** 버튼으로 추가합니다.

검증은 `powershell -NoProfile -File NotificationServer/test-submission-conversion.ps1`, 한글 설치 PC에서 실제 변환까지 확인하려면 같은 명령에 `-Integration`을 붙입니다. `NotificationServer/check-submission-conversion.cjs`는 Playwright 예시 화면으로 파일 전달·변환 실패·취소·잘못된 응답 거부를 검사합니다. 실제 학교 서버에는 테스트 파일을 전송하지 않습니다.

### 과목·과제 수집과 대체 조회

로그인된 WebView 세션에서 Moodle 과목·과제·제출 상태 API를 먼저 시도하고, 제공되지 않으면 학교 대시보드와 과제 페이지를 읽습니다. 현재 SmartLEAD의 Coursemos 화면에서는 다음 구조를 지원합니다.

- `.course-info-container`와 `[role="main"]`의 과목·과제 목록
- 과제 표의 **종료 일시 / 제출** 열과 상세 화면의 **제출 여부**
- 한국 시간 기준 `YYYY-MM-DD HH:mm` 및 한국어 날짜 표기

학교 캘린더도 별도로 조회하므로 과목·과제 API가 차단돼도 조회 가능한 마감 일정부터 표시합니다. 캘린더 일정의 제출 완료 여부를 확인하지 못하면 **제출 확인 필요**를 표시합니다. 제출 완료 과제는 연결된 캘린더 일정과 중복 표시하지 않으며, 현재 수강 목록에 없는 지난 학기의 마감된 캘린더 과제는 제외합니다.

대체 조회에서 전체 수강 목록을 확인하기 어렵거나 조회 시간이 초과되면 확인이 필요한 상태로 표시합니다. 과목 상세의 **강의 정보**는 현재 학기의 과목 페이지와 그에 연결된 주차 페이지를 읽습니다. 일부 주차를 가져오지 못하면 확보한 주차를 표시하고 다시 확인을 안내합니다. 알림은 **학교 알림 기록 보기**로 확인할 수 있습니다.

최근 조회한 과제 상세는 2분 동안 재사용할 수 있습니다. 이미지 미리보기를 일부 가져오지 못한 상세는 다음에 열 때 다시 요청하고, 업로드·저장이 확인되면 해당 과제의 상세 정보를 갱신합니다.

## 지원 환경과 개발 범위

- **현재 검증 환경:** Windows x64, Unity 6.3 LTS 에디터, WebView2 Runtime.
- **Android 구현:** 공식 WebView AAR, 세로 화면·안전 영역, 알림·과제 수신, 터치 스크롤·스와이프 닫기, 뒤로가기, 앱 복귀 시 갱신과 터치 이동 패드를 추가했습니다. ARMv7·ARM64와 IL2CPP를 설정했습니다. Android 조건의 소스 컴파일과 통신 테스트는 통과했으며 실기기 검증은 남아 있습니다.
- **위젯·백그라운드 알림:** 홈 화면 위젯, 푸시 알림과 앱 종료 상태의 자동 조회는 아직 구현하지 않았습니다.
- **로그인 정보:** 학교 페이지에서 로그인합니다. 자동 로그인을 선택한 경우 비밀번호는 기기의 보호 저장소에 저장하며 프로젝트 파일·평문 PlayerPrefs에는 기록하지 않습니다. Windows 보호 저장소와 Android 구현을 제공하며 Android 실기기 검증은 남아 있습니다.

알림 연결의 세부 설정은 [WEBVIEW-SETUP.ko.md](WEBVIEW-SETUP.ko.md)를 참고하세요.

Android에 추가한 파일, 권한, 조작 방법과 추후 기기에서 확인할 항목은 [Android 사용 안내](docs/ANDROID.ko.md)에 정리했습니다.

## 검증

- **Unity 에디터**에서 컴파일과 9:16 화면을 확인했습니다. 예시 자료로 과목·과제 상세 열기와 뒤로 가기, 주차 목록 위치 복원을 검증했습니다.
- **Node.js 테스트 51개**가 통과했습니다. 로그인, 과목·과제 수집, 마감과 연장 기한, 알림, Unity 에셋 메타데이터를 검사합니다.
- **직접 업로드**는 파일 선택, 확장자 목록, 용량·개수 제한, 기존 파일명 보호, 저장·초안 응답을 모의 환경에서 검사했습니다. 실제 SmartLEAD 세션에서는 과제 양식을 읽고 업로드·저장 요청을 구성하는 단계까지 검증했습니다. 실제 파일 저장과 최종 제출은 별도로 확인해야 합니다.

```powershell
cd NotificationServer
node --test
```

로그인 자동 입력·자동 제출과 과제 상세 조회 검증에는 `node --test NotificationServer/login.test.mjs NotificationServer/coursework.test.mjs NotificationServer/capture.test.mjs`를 사용합니다. Windows 보호 저장소의 저장·복원·변경·삭제와 Android 보호 저장소 소스 컴파일은 `./NotificationServer/test-smartlead-credentials.ps1`로 확인합니다. 보호 저장소 테스트는 매번 고유한 가짜 계정을 만들고 종료 시 삭제합니다.

과제 HTML 상세의 DOM 검사는 프로젝트 루트에서 `node NotificationServer/check-assignment-document.cjs`를 실행한 뒤 로컬 미리보기 `http://127.0.0.1:8792`에서 확인합니다. 예시 데이터로 본문 서식, 보호 이미지·동영상 포스터, 첨부파일, 제출 표, 긴 문서 분할, 로그인 만료 처리를 검사합니다.

홈페이지 공지 파싱·학교 도메인 링크·날짜/중복 처리 검증은 프로젝트 루트에서 `./NotificationServer/test-university-notices.ps1`로 실행합니다. Unity가 생성한 `Assembly-CSharp.csproj`와 .NET 10 SDK를 사용하며 생성 파일은 `Temp/UniversityNoticeChecks`에만 만듭니다.

테스트에는 로그인 만료, 읽은 알림 기록, 과목 목록 대체 조회, Coursemos 과제 표, 마감일과 연장 기한, 캘린더 대체 조회, 응답 시간 초과 처리가 포함됩니다.

## 파일 구성

- `Assets/`: 스크립트, 씬, 리소스, 플러그인과 `.meta` 파일
- `Packages/`: Unity 패키지 목록과 잠금 파일
- `ProjectSettings/`: Unity 프로젝트 설정
- `NotificationServer/`: 선택적으로 사용하는 로컬 서버와 테스트
- `BrowserBridge/`: 브라우저 확장 기반의 보조 연결 코드
- `docs/TROUBLESHOOTING.ko.md`: 사용한 방법, 오류 원인·해결·검증 내역과 추가 기록 양식
- `docs/ANDROID.ko.md`: Android용 파일·권한·조작 방법과 실기기 확인 항목

`Library`, `Temp`, 로그, 빌드 결과물과 개인 계정의 알림 데이터는 Git에서 제외합니다. 옆에 있는 별도 CLI 비교 프로젝트도 이 저장소에는 포함하지 않습니다. Unity에서 `Library` 등은 프로젝트를 열 때 다시 생성합니다.

## 변경 사항 저장하기

Unity에서 씬과 에셋을 저장한 뒤 프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
git status
git add Assets Packages ProjectSettings NotificationServer BrowserBridge docs README.md WEBVIEW-SETUP.ko.md .gitignore .gitattributes
git commit -m "Describe the change"
git push
```

작업을 시작하기 전에는 `git pull --ff-only`로 최신 변경을 받습니다. Unity의 `.meta` 파일은 에셋과 함께 커밋해야 씬 참조가 유지됩니다. 변경 목적마다 커밋을 나누면 이전 상태를 찾기 쉽습니다.
